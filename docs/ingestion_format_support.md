# Ingestion format support and eligibility

The parser registry and the ingestion policy answer different questions:

- `configs/parser_registry.json` says which deterministic extractor is available for a file type.
- `configs/ingestion_sources.json` says which file types and categories may be considered by discovery and authorization.
- Source and document approval decisions remain separate human-controlled requirements. A parser being available grants no permission and does not make a file a candidate.

The active ingestion allowlist remains `.md`, `.html`, `.rst`, `.pdf`, and `.txt`, with the existing `documentation` category and authorization checks. The registry also contains extractors for JSON, JSONL, YAML/YML, CSV, XML, TOML, INI; Python, JavaScript/MJS, TypeScript, Java, C#, Go, Rust and shell; DOT, Go templates, CONF, Excalidraw JSON, Gliffy JSON, SVG; DOCX, XLSX and PPTX. Notebook (`.ipynb`) and SQL (`.sql`) extractors are available for development review. None of those additional extensions is ingestion eligible under current policy.

Structured formats retain key paths, row/header relationships or element names. Python source is parsed with `ast`; other source formats are extracted as bounded structural text without compilation or execution. Diagram and SVG extraction keeps textual labels and relationships rather than rendering vector assets. Office packages are read through format libraries after archive entry, expanded-size, compression-ratio and path checks. Notebook outputs are discarded. Unsupported or malformed input raises a parse error rather than falling back to a raw binary/text dump.

The 2026-11-16 unsupported inventory has 3,336 records. The extension report is generated by:

```powershell
.\.venv\Scripts\python.exe scripts/build_unsupported_extension_distribution.py
```

It writes `knowledge_base/metadata/unsupported_extension_distribution_20261116.json`. It reconciles the earlier count difference: 535 `.yaml` records were absent from the earlier 2,801 tally. Parser candidates are recommendations for human scope review only; files stay excluded until category/extension policy and evidence-backed authorization are explicitly updated.

To prepare the human license review packet, run:

```powershell
.\.venv\Scripts\python.exe scripts/build_human_license_review_package.py
```

This fetches individual arXiv abstract pages to record paper-specific rights links and retrieval status, then creates the review guide, checklist, packet and evidence inventory under `docs/` and `knowledge_base/metadata/`. It never changes `source_approvals.json` or `document_approvals.json` and never starts parsing, ingestion, embedding or indexing.
